# 극단 입력 12건 검사표 (카드 3)

검사는 `tests/extreme.html`이 편집기 코드에 직접 입력을 넣어 자동으로 실행합니다.
같은 검사를 수정 전 코드와 수정 후 코드에 각각 돌렸습니다.

- 결과 재현: 편집기를 서버로 띄운 뒤 `tests/extreme.html`을 엽니다. 맨 위에 `총 N건 · PASS · FAIL`이 나옵니다.
- 화면과 파일 비교 기준: PNG를 다시 읽어 미리보기 캔버스와 비교하고, 채널 최대 오차 3/255 이하면 일치로 봅니다(아래 "검사 기준을 바꾼 일" 참고).

## 대표 결함 전후 (T03-C15)

### 결함 1 — 투명 PNG를 JPEG로 저장하면 검정 배경 (검사 11)

- **수정 전 FAIL**: 화면의 투명 영역 alpha=0, JPEG 같은 자리 RGB=(0,0,0). 화면에서는 밝게 보이던 곳이 파일에서는 검정이 됨.
- **원인**: JPEG는 투명을 지원하지 않는데, 그리기 전에 바탕색을 깔지 않았음.
- **수정**: `render()`가 이미지를 그리기 전에 흰 바탕을 먼저 칠함. 화면과 파일이 같은 함수를 쓰므로 둘 다 같아짐.
- **수정 후 PASS**: 화면 투명 영역 alpha=255, JPEG 같은 자리 RGB=(255,255,255).

### 결함 2 — 큰 글자 + 긴 문구가 캔버스 밖으로 넘침 (검사 12)

- **수정 전 FAIL**: 글자 300px에서 31줄이 되어 글자 덩어리가 y=-5265~6345로 나감(캔버스 높이 1080). 대부분의 글자가 화면과 파일 모두에서 잘림.
- **원인**: 줄 수만 늘어나고 글자 크기는 그대로였음.
- **수정**: 글자 덩어리 높이가 캔버스 높이의 96%를 넘으면 글자 크기를 조금씩 줄여 전부 보이게 함(최소 12px). 줄였을 때는 화면에 "300px → 88px로 자동으로 줄였어요"라고 알려 줌.
- **수정 후 PASS**: 9줄, 88px, 블록 y=47~1033 (캔버스 높이 1080 안).

## 검사 기준을 바꾼 일 (정직한 기록)

첫 실행에서 검사 09가 1:1에서 FAIL로 나왔습니다. 확인해 보니 위치·잘림·줄바꿈의 차이가 아니라 **그림 엔진의 반올림 흔들림(채널 최대 오차 2/255)** 이었고, 같은 입력을 다시 돌리면 0이 나오기도 했습니다.
이건 앱의 결함이 아니라 검사 기준(픽셀이 완전히 같아야 함)이 너무 엄격했던 것이라, 기준을 "채널 최대 오차 3/255 이하"로 바꿨습니다. 앱 코드는 바꾸지 않았고, 수정 전 결과도 바뀐 기준으로 다시 돌려서 기록했습니다.
글자가 밀리거나 이미지가 다르게 잘리면 오차가 수십~수백이 되므로 이 기준으로도 구분됩니다. JPEG는 손실 압축이라 이 비교에서 제외하고 검사 11에서 색만 확인합니다.
